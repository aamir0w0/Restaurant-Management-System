# Security notes
Implemented: PDO prepared statements everywhere; server-side validation; `password_hash/verify` (+rehash); session fixation protection (ID regeneration on login), HTTP-only/SameSite cookies, `Secure` over HTTPS, idle timeout; CSRF token header on state-changing requests; login throttling; per-endpoint permission checks; privilege guard (only Super Admin can assign Super Admin); CORS allow-list; upload type/size validation with random names and PHP execution disabled in `public/uploads`; no stack traces unless `APP_DEBUG=true`; audit logging without secrets; CSV formula-injection guard; React escapes output.
Not done / to review before production: HTTPS enforcement and HSTS at the web server, a password-reset email flow, security headers (CSP), per-IP global rate limiting, dependency audit (`npm audit`), a professional penetration test. Never commit `backend/.env`.

Online ordering: public endpoints are rate limited per IP, re-price every item on the server (browser totals ignored), cannot apply discounts, and order tracking requires order number + the phone used. Card data never reaches this server (Stripe-hosted checkout); payment is recorded only from a signature-verified webhook with amount/currency check and idempotency key. Gateway secrets live in backend/.env only. Theme/receipt changes are restricted to the Super Admin role.
